## Design

### Problem statement

`cnn@gs2` on grid_lines (fno-stable, recipe: `central_mask` weighting + `amplitude` forward + MAE + `real_imag` head) converges to flat amplitude (native amp MAE 0.5367 @5ep / 0.56 @20ep vs constant-field baseline 0.523) while phase reconstructs (SSIM 0.727). The same recipe at gs1 scores 0.140. Three verified code fixes (inference reroute, per-patch offsets, merge normalization) changed the failure signature but not the outcome.

RCA Round 3 (`.superpowers/sdd/ext/task-gs2-flat-amp-rca.md` §ROUND 3) established with corrected instruments:
- Dataset geometry and torch merge/extract conventions are exactly consistent (sub-pixel shift oracles, delta-spike translation oracle).
- The post-fix training objective rewards true amplitude along a flat→GT contrast path in both merge modes.
- The trained model sits in a self-consistent non-physical minimum: group phase coherence 0.78 (GT 0.985), merged-canvas amplitude uncorrelated with GT (corr ≈ 0), empirical loss 0.115 *below* GT's 0.158.
- Instrument caveat now on record: stored `Y_I` labels are ILLUMINATED (`|P·O|`, `ptycho/diffsim.py:123-142`) while `Y_phi` is pre-illumination — every GT-through-forward probe must de-probe amplitude (`O = (Y_I/|P|)·e^{iY_phi}`) or it applies the probe twice. All Round-1/2 GT-loss numbers are void for this reason.

### Why main is the reference (decision record)

User directive 2026-07-07: the phase-1 `varpro-ablation` branch may itself be corrupted relative to main; **use origin/main as the reference implementation**. Supporting facts found during setup:

1. Main's mainline `ForwardModel` trains gs2 exclusively through `reassemble_patches_position_real_probe(use_probe_weights=True)` + `RectangularScaledDiffraction` (intensity units) + Poisson loss on count data, with a shared real/imag decoder. The `central_mask` helper exists on main only in a secondary legacy class.
2. Therefore the failing grid_lines recipe diverges from the reference in **merge weighting, physics forward, and loss simultaneously** — and the probe-weighted merge is precisely the path that crashes in the grid_lines pipeline (`ptycho_torch/helper.py:259` probe-layout assumption). Main-parity gs2 has never executed on fno-stable.
3. The ported ablation runner's base arms do not pin `physics_forward_mode`; fno-stable's default is `'amplitude'` (`ptycho_torch/config_params.py:158`), while main has no knob (rect is the only forward). As ported, the "replication" arms silently train a different forward than main — a genuine port divergence to be recorded as a finding.
4. Known blocker discovered 2026-07-07: `origin/main`'s `python -m ptycho_torch.train` CLI fails at the config factory (`InferenceConfig.__init__() got an unexpected keyword argument 'log_patch_stats'`) in a clean clone with clean clone-local imports (verified via `__file__`). The reference entrypoint itself needs a minimal, *disclosed* repair (Task A0) before any reference number exists. Phase-1 presumably ran because the ablation branch modified train.py — consistent with the user's distrust of that branch. **Update (A0 walk):** the CLI is 7+ clerical defects deep at main HEAD (never runnable as published); the `varpro-ablation` branch's early `fix:` commits are the historical runbook for the same defects and are borrowed hunk-by-hunk only where main's own in-tree tests pin the behavior.
5. **Phase-1 reinterpretation (2026-07-07, B1 follow-up):** fno-stable's torch defaults are `cnn_output_mode='amp_phase'` (config_params.py:96) and `physics_forward_mode='amplitude'`; the phase-1 matrix_dl base arms pinned neither knob. The recorded "gs2 ≈ gs1" phase-1 evidence therefore came from **amp_phase heads + amplitude forward** — not from the real_imag/VarPro recipe at all (artifacts record neither knob; inferred from code defaults). Main's PT model, by contrast, has ONLY real/imag decoder branches (no amp_phase implementation exists on main's PT side — A0 static inspection). Lane A is thus the first genuine real_imag/rect/Poisson gs2 evidence in this initiative, and Lane B's parity arms (with both knobs pinned) are expected to differ from the recorded phase-1 numbers by construction.

### Readout definition (shared by all lanes)

For each trained checkpoint: stitch the test-split reconstruction with the lane's own inference machinery, then report against GT object:
- `amp_corr` — Pearson correlation of stitched amplitude vs GT amplitude over the scan-covered region;
- `amp_mae_scalefree` — L1 after per-image optimal scalar (protects against benign global-scale offsets);
- `flat_baseline` — the same MAE for a constant field at the GT mean (the "is it better than predicting a constant" bar);
- gs1 control trained identically (defines "working" on that data);
- reconstruction PNG (visual confirmation; metrics alone have been misleading in this initiative).

**Verdict rules:** Lane A gs2 ≥ clearly above flat baseline and comparable to its gs1 control → "reference works"; Lane B within tolerance (amp_corr ±0.05, MAE ±10%) of Lane A → port not regressed; Lane B materially worse → regression → bisect (use `~/.claude/skills/git-bisect-debugging`; clone already exists).
